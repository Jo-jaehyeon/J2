# 디지털 테이머 · 용의 눈 호수

Unity **6000.6.0f1**에서 `Assets/Scenes/DragonEyeLake.unity`를 열고 **Play**를 누르세요. 권장 비율은 16:9 또는 16:10입니다. 별도 서버나 아트 다운로드는 필요 없습니다.

처음에는 **DigiTactics 메인 화면**이 열립니다. **싱글 플레이**를 눌러야 라운드와 수입·타이머가 시작됩니다. **멀티 플레이**는 TODO 안내만 표시하며 아직 세션을 만들지 않습니다. 생성한 디지털 월드 배경은 `Assets/Resources/UI/DigiTacticsMainBackground.png`에 있으며, 사용 도구와 전체 프롬프트는 `Docs/MainMenuBackground.md`에 기록했습니다.

칸 기반 AI·메인 화면 검증: 규칙 검사 **37,566개**, Windows 플레이어 검사 **83개 통과**. 로그는 `Logs/grid-menu-build.log`, `Logs/grid-menu-runtime.log`입니다. UI 전체의 수동 시각 검수는 포함하지 않았습니다.

## 전장과 조작

- 아군은 아래, 적은 위에 배치합니다. 각 진영은 **8열 × 4행, 32칸**입니다. 플레이어 레벨이 실제 배치 한도이며 최대 레벨과 배치 한도는 **32**입니다.
- 양쪽 대기석은 각각 **정사각형 10칸**입니다. 아군 기물은 빈 칸으로 이동하거나 다른 기물과 자리를 교환할 수 있습니다. 적 대기석은 멀티 전환을 위한 빈 공간입니다.
- 대기석 기물 **더블 클릭** → 해당 기물만 첫 빈 전장 칸에 자동배치.
- **좌클릭** → 아군·적군·대기석 기물의 스탯을 좌측 패널에서 조회. 전투 중에는 현재 HP/SP를 표시합니다.
- **우클릭 드래그** → 전장 수동배치, 전장·대기석 간 교환, 대기석 내부 이동·교환. 적 진영이나 전장 밖에 놓으면 취소됩니다.
- 준비 시간 **30초가 지나면 자동 전투**합니다. 준비 완료 버튼은 없습니다. Escape와 포커스 이탈은 드래그를 취소합니다.
- 전투에서도 기물은 한 칸을 점유합니다. 이동 중에는 출발 칸과 도착 칸을 예약하며 다른 기물과 겹치거나 서로 자리를 관통하지 않습니다. 빈 인접 칸으로 이동하고, 막힌 모서리를 대각선으로 통과하지 않습니다.
- 사거리는 **대각선을 포함해 맞닿은 8칸 기준 1~4칸**입니다. 양 진영 사이 철로는 사거리 칸 수에서 제외합니다. 내 최전방에서 상대 최전방은 1칸, 상대 두 번째 줄은 2칸입니다. 기차는 계속 이동·공격 경로를 막습니다. 공격 가능한 빈 칸까지 경로를 찾으며 통로가 없으면 기다립니다.
- 상단에는 라운드와 타이머만, **우측에는 플레이어 체력**, 좌측 하단에는 레벨·XP 구매 버튼, 상점 바로 위에는 골드와 현재 레벨의 코스트별 확률을 표시합니다.
- 기물 선택 창은 라운드 시작에 아래에서 올라옵니다. 우측 하단 버튼으로 열고 닫을 수 있으며 전투 시작 시 닫힙니다. 전투 중에는 열람만 가능합니다.

## 호수와 기차

츠메몬은 제공된 정면·측면·후면을 참고한 별도 로우폴리 프리팹입니다. `Assets/Resources/Digimon/Tsumemon/Tsumemon.prefab`을 열면 몸통·외눈·촉수·다리·발톱의 메시와 재질을 편집할 수 있습니다. 같은 폴더에 `Idle`, `Walk`, `Attack`, `Special`, `Hit`, `Death`의 6개 `.anim` 클립이 있습니다. Transform 관절과 Unity Animation 컴포넌트를 사용하는 애니메이션이며 `ArenaUnitAnimation`이 실제 전투 이벤트에 연결합니다. 사망 시 약 0.85초 동안 쓰러짐을 표시한 뒤 숨깁니다. 디지몬 테이블의 츠메몬 외형 프리팹 연결을 완료했습니다.

`Digital Arena > Build Tsumemon Assets`는 원본 생성 코드로 이 폴더의 에셋을 다시 생성하므로 직접 수정한 에셋을 덮어씁니다. 일반 플레이에는 실행할 필요가 없습니다. 정면·측면·후면과 사선 렌더링은 `Logs/Tsumemon`에 있습니다.

츠메몬 적용 검증: Unity 빌드 성공, 규칙 검사 4,123개 및 플레이어 검사 79개 통과. 6개 클립의 샘플링, 이동 포즈 변화, 공격·특수 공격·피격 트리거, 사망 애니메이션 완료를 확인했습니다. 로그는 `Logs/tsumemon-build.log`, `Logs/tsumemon-runtime.log`입니다.

밝은 호수, 모래 물가, 숲과 산, 물에 잠긴 기울어진 송전탑, 초록색·크림색 전차를 입체 메시로 구성했습니다. 첨부한 장면과 [용의 눈 호수 설정](https://wikimon.net/Dragon_Eye_Lake)을 참고했습니다. 기물과 상점 초상화 모두 같은 입체 모델을 사용합니다.

- 철로는 양 진영 사이를 가로지릅니다. 전차는 매 라운드 준비 시작에 **오른쪽에서 왼쪽으로 1.5칸** 이동하며 약 1.2초 동안 이동 애니메이션을 보여줍니다.
- 전투 중에는 전차 위치가 고정됩니다.
- 전장 왼쪽 경계를 벗어난 라운드를 R이라 하면 R+1, R+2에는 없고 **R+3에 오른쪽으로 재등장**합니다.
- 전차는 장식이 아닌 장애물입니다. 기물은 전차의 모서리를 돌아가는 짧은 경로를 계산하며, 원거리 공격도 전차를 관통하지 않습니다. 매 라운드 열린 통로에 맞춰 배치하세요.
- 기차 위치·게임 상태·재고는 재시작 시 모두 초기화됩니다.

## 경제와 진화

- 시작 체력 **100**, 초기 자금 **5pt**, 레벨 **1**. 라운드 시작 수입은 `3 + floor(지급 전 골드 / 10)`입니다. 첫 준비 화면에서는 초기 자금 5 + 첫 라운드 수입 3 = **8pt**를 보유합니다.
- 골드 범위에서 원하는 후보를 **개별 선택하여 0~5개 구매**할 수 있습니다. 자동 구매는 없습니다. 각 후보는 한 번만 구매할 수 있고, 구매한 슬롯은 빈 칸으로 남습니다. 창을 다시 열어도 후보가 갱신되지 않습니다.
- 가격: 깜몬 1 / 코로몬 2 / 아구몬 3 / 그레이몬 4 / 메탈그레이몬 5pt. 워그레이몬은 합성 전용입니다.
- 전장과 대기석을 합쳐 같은 기물 3개가 모이면 다음 단계로 자동 진화합니다. 연쇄 진화와 전장 위치 유지가 적용됩니다.
- **4pt로 4XP**를 구매합니다. 전투 종료 시 승패와 관계없이 **플레이어 기본 XP 2**를 한 번 지급합니다. 레벨별 테이블의 필요 XP를 채우면 레벨과 배치 한도 +1, 초과 XP는 이월합니다. 기본 필요 XP는 10이며 한 번에 여러 레벨 상승도 가능합니다.
- 스테이지당 8라운드. 크립은 쿠라몬 → 츠메몬 → 케라몬 → 크리사리몬 → 인펠몬 → 디아블로몬 → 아마게몬 순으로 강해집니다.
- 패배 피해는 `남은 크립 수 × 스테이지 × 2`입니다. 전투는 최대 **30초**이며 시간 초과도 패배입니다. 승리 팝업은 표시하지 않습니다. 전투 후 소유 기물은 회복하고, 체력이 남아 있다면 4초 뒤 다음 라운드로 넘어갑니다.
- 체력 0이면 중앙에 **패배했습니다**, 아래에 **게임 재시작 / 게임 종료** 버튼을 표시합니다. Editor에서는 게임 종료가 Play 모드를 종료합니다.

## 기물 스탯과 상성

Unity 메뉴 **Digital Arena > Digimon Table**에서 기물을 추가·복제·삭제하고 이름, HP, 최대 SP, ATK, DEF, INT, SPD, 기본 공격 사거리, 공격 타입, 타입, 속성을 수정합니다. 종수는 고정되어 있지 않으며 아군과 크립 각각 최소 1종만 필요합니다. JSON을 직접 편집할 필요는 없습니다. 저장 파일은 `Assets/Resources/DigimonCatalog.json`이며 **저장 후 새 게임부터 적용**됩니다.

1. 플레이어 또는 크립 탭에서 **새 기물 추가** 또는 **선택 기물 복제**를 누릅니다. 고유 ID는 자동 생성되며 이름은 자유롭게 바꿀 수 있습니다.
2. 플레이어 기물은 구매 코스트 1~5와 3개 합성 시 진화 대상을 선택합니다. 코스트 0은 합성 전용, 진화 대상 없음은 합성하지 않는 기물입니다. 이름이나 배열 순서가 달라도 ID로 연결됩니다.
3. 크립은 등장 시작 스테이지를 지정합니다. 현재 스테이지 이하 중 가장 높은 시작 스테이지의 크립이 등장하며, 같은 스테이지에 여러 종을 지정하면 순서대로 섞여 등장합니다.
4. 기본 도형 외형 번호를 선택하거나 외형 프리팹을 지정합니다. 프리팹은 `Assets/Resources` 아래에 저장하고 필드에 드래그하세요. 원점이 발밑, 높이 약 2 유닛인 외형을 기준으로 전장과 초상화에 사용합니다. 프리팹 미지정 시 기본 도형을 사용합니다. 프리팹 파일 생성만으로 자동 등록되지는 않습니다.
5. 저장하고 게임을 재시작합니다. 편집 중인 변경은 진행 중인 게임에 즉시 반영되지 않습니다. 다른 기물이 진화 대상으로 참조하는 행은 연결을 해제한 뒤 삭제할 수 있습니다. 중복 ID, 순환 진화, 누락된 대상·프리팹은 저장 검증으로 차단합니다.

- 물리형 기본 공격·특수 능력은 ATK, 특수형은 INT를 사용합니다. SPD는 이동속도(칸/초)이며 공격 간격은 기존 단계별 고정값입니다. 기본 공격 사거리는 정수 슬라이더 1~4로 설정합니다. 기존 실수 값은 가까운 정수로 변환했습니다(1.5 → 2).
- 피해 = `공격 수치 × 스킬 배율 × 100/(100+DEF) × 타입 배율 × 속성 배율`. 기본 공격 배율은 1, DEF 100이면 피해가 절반입니다.
- 백신 → 바이러스 → 데이터 → 백신은 2배. 언노운 → 백신/바이러스/데이터, 백신/바이러스/데이터 → 속성없음은 1.1배. 프리는 무상성입니다.
- 물 → 불 → 풀 → 물, 전기 → 바람 → 땅 → 전기, 빛 ↔ 어둠은 1.5배. 명시되지 않은 방향은 1배입니다. 타입과 속성은 곱연산으로 중첩합니다.
- SP는 매 전투 0부터 시작하며 기본 공격마다 기본 20을 얻습니다. 가득 찬 다음 공격에서 기본 2배 특수 공격 후 0이 됩니다. 최대 SP·공격당 SP·스킬 배율도 테이블에서 조절합니다. 현재 특수 능력은 공통 단일 대상 공격입니다.
- 상점 우측 상단 원형 배지는 중앙 상징으로 타입, 배경색으로 속성을 표시합니다. 불 빨강 / 물 파랑 / 풀 연두 / 전기 노랑 / 바람 하늘 / 땅 갈색 / 빛 흰색 / 어둠 검정 / 무 회색. 카드 하단에도 타입·속성 이름을 표시합니다.
- 크립 HP/ATK/INT에는 기존 스테이지·라운드 배율이 적용됩니다. 준비 중 상세 패널에도 배율을 적용한 수치를 표시합니다.

## 확률과 재고 데이터 테이블

Unity 메뉴 **Digital Arena > Balance Table**에서 다음 항목을 수정하고 **저장**하세요.

- 레벨 1~32별 1~5코스트 등장 확률. 각 행의 합계는 100%여야 합니다.
- 레벨 1~31의 **다음 레벨 필요 XP**. 해당 레벨에서 다음 레벨까지 필요한 값이며 범위는 1~1,000,000입니다. 레벨 32는 MAX로 표시합니다. XP 구매·전투 보상·인게임 XP 표시와 진행 막대가 이 값을 사용합니다.
- 코스트별 구매 가능 총 수량. 기본값은 **60 / 45 / 35 / 25 / 18**입니다.

실제 데이터는 `Assets/Resources/ArenaBalance.json`입니다. 저장한 설정은 **새 게임부터 적용**됩니다. 수량 0이나 음수 확률·합계 오류는 각각 재고 없음 처리 또는 저장 검증으로 다룹니다.

수량은 한 게임 동안 구매 가능한 유한 재고입니다. 후보 추첨 시 한 기씩 임시 예약하고, 미구매 후보는 다음 라운드에 반환합니다. 구매한 재고는 소모되며 진화 시 반환하지 않습니다. 합성으로 만들어진 상위 단계는 상위 코스트 재고를 소모하지 않습니다. 재고가 소진된 코스트는 추첨에서 제외하고 나머지 확률을 재정규화합니다. 등장 가능한 재고가 없으면 빈 후보가 표시됩니다.

같은 코스트로 등록된 여러 종은 해당 코스트의 재고를 공유합니다. 코스트를 추첨한 뒤 그 안에서 기물을 균등 추첨합니다. 등록된 기물이 없는 코스트는 추첨에서 제외됩니다. 밸런스 표 열 제목에는 기물 이름 없이 `1코스트`~`5코스트`만 표시합니다.

## 구현과 검증

- `ArenaRules.cs`: 구매·유한 재고·대기석 슬롯·배치·합성·체력·XP.
- `DigimonCatalog.cs` / `DigimonTableEditor.cs`: 기물 등록·ID·코스트·진화·외형·스탯·타입·속성과 GUI 편집.
- `ArenaBalance.cs` / `ArenaBalanceEditor.cs`: 데이터 테이블과 유효성 검사.
- `ArenaTrain.cs` / `ArenaBattle.cs`: 기차의 라운드 주기, 장애물 우회와 공격 차단, 자동 전투.
- `ArenaWorld3D.cs` / `ArenaSolid.shader`: 호수·전차·입체 기물·초상화와 카메라. Built-in 렌더링 사용.
- `DigitalArenaGame.cs`: 타이머, 상점 패널, 마우스 조작, 체력과 게임 종료 UI.

`Tools/Verify-Arena.ps1` 또는 Unity 메뉴 `Digital Arena > Validate Prototype Rules`로 규칙을 검증할 수 있습니다. 전차 관통 방지, 재등장 주기, 5개 구매, 재고 반환·소진, 대기석 교환, 32칸 경계, 체력·XP·진화를 포함합니다.

`ArenaBuild.BuildSmoke`는 새 씬을 저장하고 Windows 개발 빌드를 `Builds/DigitalArena/DigitalArena.exe`에 만듭니다. `-arena-smoke` 옵션으로 실행하면 실제 플레이어에서 렌더링·좌표 선택·더블 클릭 및 드래그 입력 경로·자동 전투·재시작을 검증합니다. `Logs/Arena3D`의 캡처는 UI를 제외한 전장 카메라 렌더링입니다. 저장/불러오기·리롤·판매·멀티플레이·고유 스킬·사운드는 포함하지 않습니다.

규칙 검사는 타입/속성 전체 조합, 방어력·공격 타입·SP·SPD·30초 제한까지 포함합니다. 통합 검사는 입력 처리 함수에 마우스 동작을 전달하며 물리적인 마우스를 직접 조작하는 검사는 아닙니다. 최신 로그는 `Logs/arena-data-build.log`와 `Logs/arena-data-runtime.log`에 있습니다.

기물 확장 검증: Unity 및 .NET 규칙 검사 **4,123개**, Windows 플레이어 통합 검사 **65개 통과**. 13종을 넘긴 신규 기물의 추첨·구매·진화·초상화·모델·전투 참여를 확인했습니다. 로그는 `Logs/arena-catalog-build.log`, `Logs/arena-catalog-runtime.log`에 있습니다. UI 전체의 수동 시각 검수는 포함하지 않았습니다.
